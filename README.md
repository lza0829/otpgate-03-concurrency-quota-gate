## 并发槽位闸（投递互斥）

全局唯一口径：**硬闸拒收-零溢出** —— 槽位耗尽则投递事务匣整笔拒收，
名额已满的投递不得进入「投递中」、不得计入路况在途、不得留下假成功占用。

- 名额判定与验码单状态翻转合并为**一条原子条件 UPDATE**，跑在单个 SQLite
  写事务（WAL + busy_timeout 串行化写者），无 TOCTOU；
- 读侧（通道册槽位列、`/槽位` 探针、路况、轧差）与写侧（投递闸）共用
  `app/services/slots.py::channel_slots` 同一判定；
- 满槽返回 409，单据保持投递前状态，同事务写 `dispatch_rejections` 拒因与
  「槽位闸/拒投」事件痕；失败整体回滚，无脏名额；
- `Idempotency-Key` 请求头存档首次结局（含状态码），同键重放只返回存档，
  双投/重试只有一种占用结局；
- `overflow_tickets` 溢出票位保留为空表：空表本身即「无超槽、无假占用」的
  可核夹具，轧差「轧差溢出桶」恒为 0，非 0 即超槽事故。

收口不变量：任意已提交事务后，每个通道
`投递中占用(按 failover_channel_id 归属) <= concurrency_limit`。

### 复现矩阵夹具

`backend/tests/test_slot_gate.py`（真实 uvicorn 线程 + HTTP 并发）：

1. 满槽再投 —— 409 整笔拒收，不进在途、无假占用；
2. 释放名额后再投 —— 回执释放同事务，随后投递成功；
3. 双投对撞 —— 两笔抢最后名额，一成一拒，结局唯一；
4. 同单并发双投 —— 原子条件 UPDATE 保证只投出一次；
5. 半截脏名额 —— 事务中途失败整笔回滚，名额/状态/事件痕回到投递前；
6. 同键重放（含并行同键）—— 存档结局重放，不产生第二笔占用；
7. 读写同源 —— 通道册/探针/路况/轧差占用数完全一致；
8. 失败/切备释放名额 —— 中断回滚后无悬挂占用。
